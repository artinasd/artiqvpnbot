# ArtiQ VPN Telegram Bot

Telegram storefront + persistent orders + automatic PasarGuard provisioning, designed for Vercel serverless deployment and Upstash Redis.

## Current architecture

```text
Telegram
  -> Vercel webhook
  -> persistent order/state in Upstash Redis
  -> receipt stored + forwarded to admin
  -> automatic fulfillment (no approval gate)
  -> PasarGuard Panel API
  -> user + all available groups + traffic/expiry/HWID
  -> subscription URL
  -> Telegram delivery
```

PasarGuard remains the source of truth for VPN configuration. The bot never generates VLESS/WireGuard/Xray configuration itself.

## PasarGuard 5.2.1 setup

The bot uses direct user creation because templates are not required and may be disabled by the panel administrator.

The bot reads `/api/groups/simple` and assigns **all available groups** to each newly created user. PasarGuard groups determine which inbounds/hosts appear in a user's subscription.

Create an API key in PasarGuard and give it the permissions required to read groups and create/read/update/delete users. PasarGuard 5.x API keys authenticate with the `X-Api-Key` header.

The panel URL may contain `/dashboard/`, but the bot base URL must be the origin only:

```text
PASARGUARD_BASE_URL=https://zerofee.ok-exor.ir
```

Do not use `/dashboard/` in the base URL.

## Username rules

Paid/test bot-created usernames are generated by `lib/username.js`.

- Custom name: `TG_<custom>_<random4>`
- Telegram username: `TG_<telegram_username>_<random4>`
- No Telegram username/custom name: `TG@AtiqVPN_<random4>`
- Only ASCII letters, numbers, `_`, and `@` are accepted.
- Persian/Arabic characters, whitespace, emoji, dots, hyphens and other symbols are rejected.
- `TG_` is stripped from a user-supplied custom name so it cannot be duplicated.
- The fallback deliberately avoids `_@` as requested; this is the only exception to the normal `TG_` prefix form.

Usernames are immutable after PasarGuard creation.

## Plans and HWID

Traffic plans use `hwid_limit = 0`.

Unlimited plans use `hwid_limit = 1`.

Traffic limits are stored as bytes and expiry is calculated server-side in UTC.

Custom plans preserve the existing pricing rule:

- up to 51 GB: 4,000 تومان / GB
- above 51 GB: 3,000 تومان / GB
- 1–1000 GB
- 1–150 days

## Payment behavior

A receipt is evidence/audit information, not payment verification.

```text
AWAITING_PAYMENT
  -> RECEIPT_SUBMITTED
  -> PROVISIONING
  -> PASARGUARD_USER_CREATED
  -> SUBSCRIPTION_RETRIEVED
  -> FULFILLED
```

The administrator receives the receipt immediately but does **not** approve the order. An admin-only `❌ پرداخت نامعتبر / غیرفعال کردن` action can later disable the associated PasarGuard user and record `PAYMENT_LATER_REJECTED`.

## Idempotency

- Every order has a persistent order ID.
- Fulfillment uses a Redis lock.
- The final generated username is persisted before remote creation.
- If PasarGuard creates a user but the response is lost, retry searches for the same username and verifies the order note before reusing it.
- Username collisions cause a new 4-character suffix and retry, bounded to 10 attempts.
- Existing PasarGuard users are never overwritten merely because their username exists.
- Renewals modify the existing PasarGuard user ID instead of creating a second account.

## Vercel environment variables

Copy `.env.example` into your deployment configuration and provide real values in Vercel. Never commit the real values.

Required:

```text
BOT_TOKEN
ADMIN_ID
WEBHOOK_SECRET
UPSTASH_REDIS_REST_URL
UPSTASH_REDIS_REST_TOKEN
PASARGUARD_BASE_URL
PASARGUARD_API_KEY
BANK_DETAILS
```

Optional:

```text
SUPPORT_USERNAME
PASARGUARD_API_KEY_HEADER=X-Api-Key
PASARGUARD_TIMEOUT_MS=5000
TEST_TRAFFIC_GB=1
TEST_DURATION_DAYS=3
TEST_HWID_LIMIT=0
```

`@AtiqVPN` is intentionally not configurable.

## Deployment

1. Import this GitHub repository into Vercel.
2. Add the environment variables above.
3. Deploy.
4. Set the Telegram webhook to the deployed `/api` function and include the same `WEBHOOK_SECRET` as Telegram's secret token.
5. Confirm PasarGuard is reachable from the public internet over HTTPS.
6. Confirm the PasarGuard API key can read groups and manage users.
7. Send `/start` and test the automated test account.
8. Run a small paid test order and submit a receipt.

The bot requires no paid VPS, queue, worker or monitoring service.

## PasarGuard networking

The PasarGuard API must be reachable from Vercel. A private `localhost`, LAN-only address, or SSH port-forward is not sufficient for production. Keep TLS verification enabled.

## Admin commands

- `/pingdb` — Redis connectivity
- `/users` — registered Telegram users
- `/broadcast text` — broadcast to active users
- `/status` — Telegram/Redis/PasarGuard health and order counts
- `/orders` — recent orders
- `/failed` — failed fulfillments

## Testing
